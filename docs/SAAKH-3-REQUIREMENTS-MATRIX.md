# Saakh 3.0 requirements and acceptance map

| Requirement | Actual implementation | Evidence / boundary |
|---|---|---|
| Payroll | Employee registration/edit/archive/search; effective salary versions; reviewed attendance/leave/overtime; effective contribution assumptions; draft/calculated/review/approval/confirmation/finalization; payslip; partial/batch payments; reversals; advances/remittances; monthly/department/employee reports | operations3, Payroll3, documents3; unit/integration tests and browser Scenario A. Monthly demo; no certified statutory engine. |
| Sales returns | Source quantities and original prices/discount/tax; eligibility/reservations; partial/multiple returns; review/approval/credit; restock/quarantine/write-off; customer liability/refund/allocation/reversal; acknowledgment/credit print/PDF; CSV | Return ledger and source evidence; browser Scenario B; no cash on approval. |
| Purchase returns | Draft/submitted/approved; distinct dispatch; supplier communication/dispute; reference-backed full/partial supplier credits; unpaid bill adjustment or refund receivable; separate receipt/allocation/reversal; stock/journal reports | Browser Scenario C; quantity and accounting tests. Internal form is not supplier-issued credit. |
| Automatic invoicing | Existing form/service reused; blank auto FY number/prefix; inline new/saved/guest customer; stock/ledger/payment atomic save; idempotent submission token; immutable numbers and no cancellation reuse; preview/PDF/print, duplicate draft, source evidence | Browser B/D and unit tests. Ordinary PDF, no statutory IRN or delivery integration. |
| Customers | Shared Party model, profile registration/edit/archive, duplicate resolution, search/filter/sort, invoice/payment/return/credit history and deterministic metrics; date-filtered statement, CSV/PDF | Customer reconciliation tests; browser D. No production tenant security claim. |
| Shared accounting | Existing integer-paise journals, source IDs, validations, original balances/P&L/passbook extended; no second ledger; payroll source-payable reconciliation; return conservation; reversible corrections | Scenario E, operations3.test and existing regressions. |
| Dashboard, forecasts, reports | Linked operations cards; finalized unpaid salary scheduled once; only explicitly documented, undisputed refund commitments forecast; CSV/print/PDF and activity search/type filters/source navigation | Forecast tests and report browser checks. Assumptions remain uncertain. |
| Migration and recovery | v1→v2 additive migration in existing IndexedDB key; no old records deleted; validation; original invalid-record export and write block; explicit reset; opt-in coherent demo seed | Migration/store tests and browser fixture/refresh scenario. |
| Roles, responsive navigation | Existing theme tokens; grouped desktop/mobile navigation; payroll/admin/manager/auditor demo views; sensitive payroll guard; eight requested widths and keyboard form opening | New Pages browser suite plus original theme/keyboard tests. |
| Pages compatibility and release | /Saakh1/ base, production HashRouter and 404 migration preserved; only deploy.yml uploads dist; heavy PDF loaded on demand | Scenario F, full Pages regression and exact-live-SHA checks when published. |

Acceptance A–F are evaluated by the test report; counts there are actual executed results, not promises. See KNOWN-LIMITATIONS for explicit production/statutory and workflow policy boundaries.
