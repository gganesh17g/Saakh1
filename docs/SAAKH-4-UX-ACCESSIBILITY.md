# Saakh 4.0 UX and accessibility

System appearance is the default. An early head script applies the saved preference before React; the existing header cycles Light/Dark/System. Storage failures fall back to a session preference. Comfortable and Compact spacing, reduced motion, enhanced workspace borders, chart legend visibility and 2D/3D preferences are independent of ledger data.

The header separates normal Account links from Explore Demo Roles. Search uses Ctrl/Cmd+K and a native modal; Escape closes panels. Create lists only supported role-eligible workflows. Customer forms use a native modal drawer and full-screen mobile layout. Financial confirmation controls retain explicit action language and source review.

Desktop navigation groups retain expansion preferences and reveal an active destination. Mobile navigation uses existing permitted destinations with a More menu and safe-area padding. Mobile table cards keep source records and semantic labels rather than displaying different metrics. Record sections and chart equivalents retain textual financial values.

The optional checklist derives from actual business/customer/item/invoice/opening-journal records. It is not a compliance checklist. Help explains application terms; the deterministic Assistant explains local business records and never executes financial actions. Assistant context is session-only and scoped by business and role.

Final tested widths, keyboard checks, console findings and screenshots are recorded in `SAAKH-4-TEST-RESULTS.md`. This is not an independent WCAG certification or screen-reader audit. Native OS print dialogs and arbitrary hardware/touch devices are not automated.
